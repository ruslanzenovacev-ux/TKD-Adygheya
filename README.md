# Приложение секции тхэквондо

Родители покупают абонементы через СБП и видят остаток занятий. Тренеры отмечают посещения. Администратор настраивает группы, цены и смотрит оплаты.

## Состав

| Часть | Что это | Статус |
|---|---|---|
| `backend/` | Серверная логика: облачная функция Yandex Cloud + база YDB | ✅ готово, 30 автотестов |
| `app/` | Приложение Flutter: Android (APK) и веб-версия для iPhone, автообновление | ✅ написано, собирается на GitHub |
| `.github/workflows/build.yml` | Автосборка, подпись и выпуск новых версий | ✅ |

## Как устроено

```
Телефон (Flutter) ──HTTPS──► API Gateway ──► Cloud Function (backend/src/handler.js) ──► YDB
                                                   │   ▲
                                                   ▼   │ уведомление об оплате
                                                 ЮKassa (СБП)
```

Все серверы в России (Yandex Cloud), это требование 152-ФЗ. Своего сервера нет: функция запускается только на время запроса.

## Правила, заложенные в логику

- **Абонемент** — это пакет из N занятий со сроком действия. Срок отсчитывается со дня покупки, день покупки входит в срок.
- **Списание** идёт сначала из абонемента, который сгорает раньше. Неиспользованные занятия сгорают в полночь по Москве после последнего дня.
- **Долг.** Если занятий нет, ребёнка не разворачивают у двери: посещение записывается в долг, а следующая покупка его гасит.
- **Отметки без интернета.** Каждая отметка получает свой id прямо в телефоне, поэтому повторная отправка ничего не задваивает. Две отметки одного ребёнка в один день не засчитываются.
- **Отмена ошибочной отметки** возвращает занятие в тот же абонемент. Отметить можно только сегодня или задним числом, но не раньше чем за 31 день.
- **Новый ребёнок.** Родитель добавляет ребёнка, тренер группы или админ подтверждает. До подтверждения оплата недоступна.
- **Сумму оплаты определяет сервер.** Цена берётся из таблицы абонементов, приложение её не передаёт.
- **Зачисление.** Уведомлению от ЮKassa сервер не верит на слово: он перепроверяет платёж в ЮKassa своими ключами. Если сумма не совпадает, платёж уходит на проверку админу. Повторное уведомление ничего не начисляет.
- **Ручная оплата** (наличные или перевод) вносится админом, занятия зачисляются сразу.
- **Возврат.** По умолчанию возвращается сумма за неиспользованные занятия, остаток при этом обнуляется.
- **Отчёт для бухгалтерии** выгружается в CSV, который сразу открывается в Excel.

## Роли

| | Родитель | Тренер | Админ |
|---|---|---|---|
| Свои дети, остаток, оплата СБП | ✅ | ✅ (если тоже родитель) | ✅ |
| Дети своих групп, отметки, подтверждение новичков | — | ✅ | ✅ все группы |
| Группы, абонементы, цены, тренеры, ручные оплаты, возвраты, отчёты | — | — | ✅ |

Админом становится почта из `ADMIN_EMAILS` при первом входе. Тренер входит как обычный пользователь и вводит код приглашения от админа.

## Разработка

Нужен Node.js 22.

```bash
cd backend
npm test        # автотесты (без облака и без ЮKassa)
npm run dev     # локальный сервер http://localhost:8787 с демо-данными и тестовой оплатой
```

Демо-входы для `npm run dev`: `boss@demo.ru` (админ), `coach@demo.ru` (тренер), `mama@demo.ru` (родитель). Код входа печатается в консоли.

## Развёртывание в Yandex Cloud

Сервер выкладывается **автоматически через GitHub** (`.github/workflows/deploy-backend.yml` + `backend/deploy/deploy.sh`) при каждом изменении папки `backend/` или вручную: Actions → «Развёртывание сервера» → Run workflow. Скрипт сам создаёт сервисный аккаунт функции, базу YDB и таблицы, функцию, API Gateway и хранилище для APK и веб-версии. Повторный запуск ничего не ломает, а только выкладывает новую версию.

Что нужно сделать вручную один раз:
1. В консоли Yandex Cloud: платёжный аккаунт и уведомление о расходах (Биллинг → Бюджеты).
2. Сервисный аккаунт `github-deploy` с ролью `admin` на каталог и его **авторизованный ключ** (JSON).
3. В GitHub (Settings → Secrets and variables → Actions):
   - секреты `YC_SA_KEY_JSON` (содержимое JSON-ключа) и `YC_FOLDER_ID`;
   - переменная `ADMIN_EMAILS` — почта руководителя.
4. Позже: секреты ЮKassa (`YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`) и почты Postbox (`POSTBOX_ACCESS_KEY_ID`, `POSTBOX_SECRET_ACCESS_KEY` + переменная `MAIL_FROM`). После добавления запустите развёртывание ещё раз.

В ЮKassa (Интеграция → HTTP-уведомления) укажите адрес из итогов развёртывания: `https://<домен-шлюза>/webhooks/yookassa`, события `payment.succeeded` и `payment.canceled`.

> Модуль `src/repo/ydb.js` (работа с YDB) и отправка писем через Postbox проверяются только в облаке, на шагах 5–8. Вся остальная логика покрыта автотестами.

## Приложение (`app/`)

Одно приложение, вкладки зависят от роли:

- **Родитель:** «Мои дети». Видит остаток занятий и срок действия, добавляет ребёнка, покупает абонемент по СБП, смотрит историю посещений и платежей.
- **Тренер:** «Группы». Выбирает занятие (сегодня или прошедший день), отмечает детей касанием и подтверждает новичков. **Без интернета** отметки копятся в телефоне и отправляются сами, когда появится связь.
- **Админ:** «Управление». Все спортсмены с поиском и фильтром «заканчиваются», оплаты за месяц с выручкой, абонементы и цены, группы и тренеры (приглашение по коду), ручная оплата, перевод в другую группу, архив, возврат. В веб-версии есть выгрузка в Excel.

### Автообновление

1. В GitHub: Actions → «Сборка и выпуск» → **Run workflow**. Отметьте «Выпустить», впишите, что нового, при необходимости отметьте «Обязательное обновление».
2. GitHub собирает APK и веб-версию, подписывает APK постоянным ключом и выкладывает в Yandex Object Storage:
   - `apk/tkd-1.0.N.apk` и `apk/tkd-latest.apk` — ссылку на последний файл можно давать новым родителям;
   - `web/` — веб-версия для iPhone;
   - `version.json` — номер свежей версии и контрольная сумма APK.
3. **Android.** Приложение при запуске (не чаще раза в 6 часов) или по кнопке «Проверить обновления» видит новую версию. Оно скачивает APK, сверяет контрольную сумму и открывает системный установщик. В первый раз Android попросит разрешить установку из этого приложения.
4. **iPhone (веб-версия).** Приложение предлагает обновиться и перезагружает страницу.
5. **Обязательное обновление.** Окно нельзя закрыть, пока версия не обновлена. Это нужно, если изменился сервер.

> ⚠️ **Ключ подписи APK нельзя терять.** Если APK подписать другим ключом, Android не даст поставить его поверх старого, и всем придётся удалить приложение и установить заново. Копия ключа хранится у владельца секции отдельно от GitHub.

### Первичная настройка GitHub (один раз)

**Settings → Secrets and variables → Actions:**

| Тип | Имя | Что это |
|---|---|---|
| Secret | `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` | ключ подписи APK |
| Secret | `YC_SA_KEY_JSON`, `YC_FOLDER_ID` | доступ к Yandex Cloud: адрес сервера и выкладка обновлений берутся оттуда автоматически |
| Variable | `ADMIN_EMAILS` | почта руководителя секции (администратор) |
| Variable | `PRIVACY_URL` | страница политики конфиденциальности |
| Variable | `CLUB_NAME` | название секции на экране входа |

Пока Yandex Cloud не настроен, каждая сборка всё равно даёт APK для проверки: Actions → нужный запуск → Artifacts.
